# SoundPlayerChiyomaru 設計書

開いたファイルを軽く・高音質に再生することに絞った、Windows 11 向けの音楽プレーヤー。
この文書は、決めた仕様と、その理由、実測で分かったことをまとめたもの。

## 1. 目的とコンセプト

- ライブラリ（データベース、スキャン、タグの管理）は持たない。ファイルを開いて再生する使い方に特化する
- 優先順位: **軽さ（起動・メモリ・CPU）> 音質 > プレイリスト編集の手軽さ > 機能の多さ**
- 判断に迷ったときは、この順で決める。機能を足すときは、起動時間とメモリへの影響を実測してから入れる

## 2. スコープ

### 作るもの

- ファイルの再生（開く、ドラッグ & ドロップ、関連付け、コマンドライン引数）
- 高音質な出力（WASAPI 共有モード / 排他モード、ビットパーフェクト再生）
- その場で編集でき、保存できるプレイリスト
- 基本の再生の操作

### 作らないもの

- ライブラリ機能、ファイルの変換・エンコード、CD の取り込み
- スキン、VST、汎用のプラグインの仕組み
- ストリーミングサービスとの連携、ネットワーク再生
- タグの編集（表示だけ）
- ASIO 出力（出力の層はインターフェースで分けてあり、将来足せる）
- イコライザー、クロスフェード
- CUE シート
- Ogg Vorbis / Opus / OggFlac の再生（デコーダーの層に足せば、将来対応できる）
- インストーラー（配布はポータブルだけ）

## 3. 再生

### 3.1 対応フォーマットとデコード

- 対応: MP3、FLAC、WAV、AAC（M4A）、WMA
- デコードは NAudio と、形式ごとのリーダーで行う。WAV は `WaveFileReader`、それ以外は Media Foundation
- デコーダーの層は差し替えられる作りにしてある（`IAudioDecoder`）。拡張子から選び、開けなければ次の候補を試す
- NAudio の `AudioFileReader` は使わない。内部で 32bit float に変換するので、元のビット深度が失われる
- MP3 に NAudio の `Mp3FileReaderBase` は使わない。同じリーダーで 2 回目のシークをすると、位置が進まないままデータを返し続けた（3.1.0 で確認）
- FLAC は Media Foundation で読む。乱数のデータを FLAC にして読み戻し、16bit / 24bit、44.1〜192kHz、モノラル、6ch のすべてで、元のビット深度のまま全サンプルが一致することを確かめた
- 24bit / 32bit float の `WAVE_FORMAT_EXTENSIBLE` の WAV は、環境によっては変換に失敗して例外になる。ヘッダーを解析して、データは変えずに通常の形式として読む

### 3.2 音質・出力

#### 処理の経路は 2 つ

- **ビットパーフェクト経路**: デコードした整数 PCM を、値を変えずにデバイスへ渡す。float を経由しない
- **通常経路**: 32bit float にして、音量や ReplayGain を掛け、必要ならチャンネル数とサンプルレートを合わせてから、デバイスの形式に戻す（ディザは入れていない）

ビットパーフェクト経路になるのは、次のすべてを満たすとき。

- WASAPI 排他モードである
- 曲が 16 / 24 / 32bit の整数である
- デバイスが、同じサンプルレート・チャンネル数で、値を変えずに収まる形式を受け付ける
- 音量が最大で、ミュートしていない
- ReplayGain がオフである

2 つの経路は、出力に渡すバッファごとに選ぶ。どちらも同じデバイスの形式で書くので、音量を動かしても出力は作り直さず、音は途切れない。
乱数の 16 / 24 / 32bit を流して、出力に渡る値が元のサンプルと完全に一致することをテストで確かめている。

#### 出力モード

- WASAPI 共有モード（既定）: 形式の違いは Windows が吸収する。常に通常経路になる
- WASAPI 排他モード: デバイスが受け付ける形式を自分で決め、その形式どおりのバイト列を渡す
- 排他モードの間は、他のアプリの音（通知音を含む）がそのデバイスから鳴らなくなる。切り替える場所に、その旨を書いている

#### 排他モードの形式の決め方

曲の形式に対して、次の順に候補を試し、デバイスが最初に受け付けたものを使う。

1. 曲と同じサンプルレートで、値を変えずに収まる形式（同じビット数、次により大きい入れ物。24bit なら 24bit → 24-in-32 → 32bit）
2. 同じサンプルレートで、ビット数が減る形式
3. 別のサンプルレート（2 倍、4 倍、それより高い標準のレート、低い標準のレート、最後に共有モードの形式のレート）

- 同じ内容なら、スピーカーの配置の情報がない通常の形式を先に試し、拒否されたら配置つきの形式で確かめ直す
- モノラルの曲は、サンプルレートごとに、モノラルが受け付けられなければステレオで探す（モノラルのままリサンプリングするより、同じサンプルレートでステレオに広げるほうを選ぶ）
- リサンプリングには NAudio の `WdlResamplingSampleProvider` を使う
- どの候補も受け付けられなければ、排他モードでは再生できないので、共有モードに切り替える（ステレオのデバイスで 5.1ch の曲を再生する場合など）

NAudio の `WasapiPlayer` は、渡した形式をデバイスが受け付けないと、黙って変換する（24bit を渡すと 16bit に格下げされた）。
このため、形式の決定と詰め替えは自前で行い、そのうえで NAudio が「変換なし」と報告することを実行時に確かめる。そうでなければ、ビットパーフェクトとは表示しない。

#### 24-in-32

- 一部の USB DAC は、排他モードで「32bit の入れ物に有効 24bit」の形式しか受け付けない。この形式を候補に入れないと、24bit の曲が 16bit に格下げされる
- 24bit のデータを 32bit の入れ物の上位側に詰め、下位を 0 で埋める。値は変わらないので、ビットパーフェクトのまま
- 画面の表示は「32 bit」だけにせず、「24-in-32」のように内訳を書く

確認に使った Roland Rubix 24 が排他モードで受け付けるのは、16bit と 24-in-32 だけだった。サンプルレートは 44.1 / 48 / 96 / 192kHz で、88.2 と 176.4kHz は受け付けない。

#### 出力のビット深度の上限

- 排他モードで使う形式の上限を、「自動（既定）/ 16 bit まで / 24 bit まで」から選べる
- 上限を指定すると、有効ビット数がそれを超える整数の形式と、float の形式を候補から外す
- デバイスによって音が出ないときの切り分けに使う。上限が曲のビット数より小さければ、ビットパーフェクトではなくなる
- 共有モードには効かない

#### バッファの長さ

- 50 / 100 / 200（既定）/ 300 / 500 ミリ秒から選ぶ。共有モードと排他モードの両方に効く
- 変えると、位置を保ったまま出力を作り直す

#### 代わりの出力

- 出力は、排他モード → 同じデバイスの共有モード → 既定のデバイスの共有モード、の順に、作れるまで試す
- 代わりの出力で鳴らしているときは、理由を示す（「排他モードを使えません（他のアプリがデバイスを使用中です）。共有モードで再生しています。」など）
- 失敗の原因は HResult で見分ける（形式を受け付けない、他のアプリが使用中、排他モードが許可されていない）
- 他のアプリがデバイスを排他モードで使っているときは、共有モードでも開けないので、再生できない
- 排他モードから共有モードへ切り替わった後、排他モードが使えるようになっても、自動では戻らない（次に出力を作り直すときに試す）

#### デバイスの選択と、抜き差しへの追従

- 出力デバイスは選べる。「既定のデバイス」を選んでいる間は、Windows の既定の出力デバイスに従う
- 選んだデバイスが使えない間は既定のデバイスで再生し、使えるようになったら選んだデバイスに戻る
- デバイスの追加・削除・状態の変化・既定の変更を受け取り、「使うべきデバイスが今の出力と違えば、出力を作り直す」という 1 つの仕組みで扱う
- 出力を作り直すときは、再生の状態と位置を保つ。古い出力がまだ鳴らしていなかった分（最大でバッファの長さ）は、鳴らさずに先へ進む
- 再生中にデバイスを失った場合は、出力を作り直して同じ位置から続ける。10 秒の間に 3 回失った、または出力を作れない場合は、位置を保って一時停止にし、デバイスが使えるようになったら自動で再開する。その間に利用者が操作したら、自動の再開はしない

#### 多チャンネル

- 3 チャンネル以上の曲は、スピーカーの配置を持つ形式（`WAVE_FORMAT_EXTENSIBLE`）として出力に渡す。配置なしで渡すと、共有モードでも初期化に失敗する
- 配置つきで渡せば、デバイスのスピーカーの構成に合わせて Windows がまとめる。配置は、チャンネル数から標準の並びを仮定する

#### 音量とミュート

- 音量が最大のときは、サンプルに手を加えない（ビットパーフェクト経路の条件）
- ミュートは、このアプリの音だけを消す（Windows のミュートとは別）。再生は止めない
- 音量の設定は残すので、解除するとミュートする前の音量に戻る。ミュートの間に音量を動かすと解除する。終了すると解除される

#### 排他モードで、曲の終わりと一時停止を無音でつなぐ

- 排他モードでは、デバイスへ渡すバッファを毎回ちょうど満杯にする必要がある。NAudio 3.1.0 は、再生元が終端を示すとエラーになる
- このため、曲が終わっても出力へ終端を伝えず、無音を渡し続ける。バッファの長さの 2 倍の無音を流し終えた時点で、「曲の終わり」として扱う
- 一時停止の間も、出力を止めずに無音を渡し続け、再開したら続きの音からそのまま渡す。NAudio 3.1.0 の一時停止は、デバイスのストリームを動かしたままバッファを渡すのをやめるだけで、排他モードでは、再開した後の音にノイズが乗ることがあった
- 共有モードは、Windows が空のバッファを無音として扱うので、NAudio の一時停止をそのまま使う

#### 状態の表示

- 画面には、曲の形式（「44100 Hz / 16 bit / 2 ch」）と、ReplayGain のゲインだけを出す
- ビットパーフェクトで再生している間は、「BP」の印を出す
- 排他モードを選んでいて、音量が最大・ReplayGain がオフなのに、ビットパーフェクトにできていない間は、「× BP」の印を出し、理由をツールチップで示す
- 利用者の操作（音量、ReplayGain、共有モードの選択）で通常経路になっている間は、何も出さない
- 出力の詳しい状態（モードと経路、出力の形式、デバイス名、代わりの出力にした理由）は、「出力」メニューの先頭と、設定画面に出す

### 3.3 再生モードとギャップレス再生

- 再生モード: 通常 / 1 曲リピート / 全曲リピート / ランダム / 1Shot（今の曲が終わったら止まる）
- ランダムは止まらずに続き、同じ曲を続けて選ばない
- 「前へ」は、再生位置が 3 秒を過ぎていれば曲の先頭に戻り、そうでなければ前の曲へ移る（ランダムでは、再生した履歴をさかのぼる）
- **ギャップレス再生**: 次の曲を先に開いておき、出力を止めずに読み継ぐ
  - 共有モードでは、サンプルレートとチャンネル数が同じ曲が続くとき
  - 排他モードでは、次の曲がデバイスの形式に、同じ経路でそのまま収まるとき
  - 続けられない場合は、出力を作り直して次の曲を再生する
  - MP3 と AAC は、エンコーダーが付ける先頭・末尾の無音を取り除かない。厳密に無音が入らないのは WAV と FLAC
- **次にこの曲から再生**: 今の曲が終わったら、再生モードに関係なく指定した曲へ進み、そこからは再生モードに従う。別の曲を自分で選んだとき、指定した曲を削除したときは取り消す
- 再生中の曲をプレイリストから削除しても、再生は止めない。曲が終わると、削除する前に後ろにあった曲へ進む

### 3.4 ReplayGain

- モードは「オフ（既定）/ トラック / アルバム」
- 選んだ側の値がなければ、もう一方を使う。どちらもない曲には何も掛けない。±60 dB を超える値は、壊れたタグとみなして使わない
- クリップを避けるため、ピークのタグがあれば、ピークが最大振幅を超えないところまでゲインを抑える。ピークのタグがない曲は、上げる方向には掛けない
- 通常経路だけの機能。有効な間は、タグのない曲も含めて、排他モードでも通常経路で処理する（曲ごとに経路が変わると分かりにくいため）
- ゲインは曲ごとに持つ。ギャップレス再生で続く曲は、境界のサンプルちょうどで次の曲のゲインに切り替わる
- プリアンプの設定は設けていない

## 4. プレイリスト

このアプリの中心の機能。ライブラリを持たない代わりに、プレイリストを手軽に編集できることを重視する。

### 4.1 編集

- 追加: ファイルやフォルダのドラッグ & ドロップ、「ファイルを追加」「フォルダを追加」
- 並べ替え: 行をドラッグして動かす（複数選択のまま動かせる）
- 移動: 選択中の曲を「上へ」「下へ」「再生中の曲の次へ」「先頭へ」「最後尾へ」動かす（曲の右クリックと「編集」メニューの「移動」）
  - 離れた曲を選んでいたときは、ドラッグと同じく、移動先でひとかたまりにまとめる。「上へ」はいちばん上の選択曲の 1 つ上、「下へ」はいちばん下の選択曲の 1 つ下が移動先
  - 「再生中の曲の次へ」は並びそのものを変える（「次にこの曲から再生」は並びを変えず、次の 1 回だけその曲へ進む）。選択に再生中の曲が含まれていれば、それ以外の曲だけを動かす
  - 並びが変わらない行き先（先頭にある曲の「上へ」など）は選べない
  - 「上へ」「下へ」は Alt+↑ / Alt+↓ でもでき、動かした曲が見える位置まで追う。それ以外の行き先では追わない（送り出した後も同じ場所で作業を続けられるように）
- 削除、複数選択、すべて選択、すべて削除
- 並べ替え: ファイル名、タイトル、アーティスト、アルバムとトラック番号、フルパス、曲順（#）
- シャッフル: プレイリストの並びそのものを無作為に入れ替える（再生モードのランダムとは別）。再生中の曲は先頭に置く
- 元に戻す / やり直し（50 回まで）
- 存在しないファイルは薄く表示する
- 重複の除外: 「すでにプレイリストにある曲は追加しない」を選べる（既定はオフ）。追加するときに、同じパスの曲を除く。「開く」でプレイリストを置き換えるときは除かない
- 「削除」は一覧から外すだけで、ファイルは消さない。紛らわしくないよう、「プレイリストから削除」と書く

### 4.2 保存・読み込み・復元

- 保存の形式は **M3U8（UTF-8）**。読み込みは M3U8 / M3U / PLS
- 上書き保存ができるのは M3U8 だけ。M3U / PLS から読み込んだ場合は、名前を付けて保存する
- 相対パスで保存するかどうかを選べる
- **終了するとき、プレイリストを置き換えるときに、保存の確認はしない**
- **作業中のプレイリストは自動で保存し、次の起動で復元する**
  - 保存先は、実行ファイルの隣の `playlist.m3u8`。名前を付けて保存したものとは別
  - 編集の後 2 秒操作がなければ保存し、終了するときにも保存する
  - ファイルを指定せずに起動したら、前回のプレイリストと、選んでいた曲を復元する
  - ファイルを指定して起動したら、復元せずに、指定されたファイルで新しいプレイリストを作る
  - プレイリストファイルを 1 つだけ開いた場合は、その内容を読み込み、元のファイルを覚えておく（「上書き保存」で書き戻せる）
  - 保存は、一時ファイルに書いてから置き換える（書いている途中で落ちても壊れない）

### 4.3 表示

- 列: 曲順（#）、トラック番号、タイトル、アーティスト、アルバム、アルバムアーティスト、時間、ファイル名
- 既定で出すのは、曲順、タイトル、アーティスト、アルバム、時間、ファイル名。タイトルは常に出す
- 列の幅と順番は、見出しをドラッグして変えられる。見出しを右クリックすると、列を動かす・隠す・足すことができる
- 列は常にウィンドウの幅に収める（横スクロールはしない）。曲順・トラック番号・時間はピクセルの幅で持ち、それ以外は残りの幅を比率で分け合う。境目をドラッグすると、その左右の 2 列の間で幅をやり取りする
- 再生中の曲は色と太字で示し、曲が変わったらその行までスクロールする
- 状態の行に、曲数と、合計の再生時間を出す

#### 曲順の番号

- 曲ごとに番号を持つ。プレイリストに追加したときに、「今の最大の番号 + 1」を振る
- 移動、並べ替え、シャッフル、削除では、番号を変えない。元の順を覚えておくためのもの
- 「現在の曲順でリナンバリング」で、今の並びの順に 1 から振り直す
- 番号は終了した後も保つ。プレイリストファイルに、曲の行の前の `#CHIYOMARU-ORDER:番号` の行として書く（他のプレイヤーはコメントとして読み飛ばす）。番号が並びのとおりのときは書かない

### 4.4 タグとアートワーク

- タグの読み取りは自前の実装。読むのは、タイトル、アーティスト、アルバム、アルバムアーティスト、トラック番号、長さ、ReplayGain、埋め込みの画像だけ。書き込みはしない
- 対応する形: MP3（ID3v2.2 / 2.3 / 2.4、APEv2、ID3v1）、FLAC（Vorbis コメント、PICTURE）、M4A、WAV（ID3v2 のチャンク、LIST/INFO）、WMA
- タグは、画面を止めずに裏で読む
- 文字コードの指定がない、または Latin-1 と書かれている文字列は、UTF-8 として正しければ UTF-8、日本語の環境でシフト JIS の日本語らしければシフト JIS、どちらでもなければ Latin-1 として読む
  - Latin-1 の欧文は、シフト JIS としても復号できてしまうことが多い。復号できるだけでは採用せず、ひらがな・カタカナ・第 1 水準の漢字などに当たる 2 バイト文字か、半角カナが 3 文字以上続く並びがあるときだけ、日本語とみなす
- 複数のアーティストは「; 」でつなぐ。ID3v2.3 のアーティストに含まれる「/」は、区切りとみなさない（「AC/DC」のような名前を壊さないため）
- 壊れたファイルで止まらないよう、ファイルに書かれた大きさは、読む前に必ずファイルの残りの長さと上限で確かめる。読むブロックの数にも上限を置く
- アートワークは、タグの画像を使い、なければ曲と同じフォルダの `folder.jpg` を使う。どちらもなければ、音符の図形を出す
  - 読み込みは、曲が変わったときに別のスレッドで行う。表示する大きさに縮小して、今の曲の 1 枚だけを持つ
  - 4,000 万画素を超える画像は読まない

## 5. ファイルを開く動作

- **単一インスタンス**: 起動済みの場合は新しいウィンドウを作らず、起動済みのインスタンスにファイルを渡す
  - 名前付きミューテックスで判定し、名前付きパイプ（現在の利用者だけが接続できる）で渡す
  - 5 秒以内に届かなければ、単独のインスタンスとして起動する
  - ファイルなしで 2 つ目を起動した場合は、起動済みのウィンドウを前面に出すだけ
- **起動していない状態でファイルを渡された場合**: 前回のプレイリストは復元せず、渡されたファイルで新しいプレイリストを作って再生する
- **起動済みのインスタンスにファイルを渡された場合**: 動作を設定で選ぶ。「プレイリストを置き換えて再生」（既定）/「末尾に追加」/「追加して再生」
  - エクスプローラーで複数のファイルを選んで開くと、ファイルごとに別々のプロセスが起動する。前の要求から 0.7 秒以内に届いたファイルは、同じ操作の続きとみなして追加する
  - 重複の除外で追加されなかった曲も、「追加して再生」なら、すでにある同じ曲を再生する
- **ドラッグ & ドロップ**
  - プレイリストの中に落とすと、その位置に追加する
  - それ以外の場所に落とすと、上の設定の動作に従う
- 「ファイル」メニューの「開く」は、常にプレイリストを置き換えて再生する
- **ファイルの関連付け**: 設定画面から登録・解除する
  - 現在の利用者（`HKEY_CURRENT_USER`）にだけ書き、管理者の権限は要らない
  - 登録すると、「プログラムから開く」と、Windows の「既定のアプリ」の設定に、このアプリが現れる。既定のアプリにするかどうかは、利用者が Windows の設定で選ぶ
  - 解除は、登録で書いたものだけを消す

## 6. UI

### メインウィンドウ

- 再生の操作と、プレイリストの、1 ウィンドウの構成
- 上から、メニュー、曲の情報と操作、プレイリスト、状態の行
- 曲の情報は 2 行。1 行目は「タイトル - アーティスト」、2 行目は「アルバム - アルバムアーティスト」
  - 幅に収まらないときは、横に流して全体を読めるようにする
  - 2 行目は、タグがない曲でも行の高さを残す（曲によって配置が動かないようにする）
- アートワークは、曲の情報の左に 160 ピクセル四方で出す（右側の高さに合わせた大きさ）
- 操作のボタンはアイコン。画像やアイコンフォントは読み込まず、ベクターの図形で持つ。再生 / 一時停止は大きくして主の色で塗り、停止と再生モードは控えめにする
- エラーとお知らせは、状態の行の右側に出す（エラーは赤）。長い文は末尾を省き、全文はツールチップで読める
- ウィンドウの位置と大きさ、最大化していたかどうかを保存し、次の起動で戻す。保存した位置が今のモニターの構成で使えない場合は、画面に収まる位置へ動かす

### ミニモードと、常に手前に表示

- ミニモードは、メニュー・プレイリスト・状態の行を隠し、曲の情報と操作だけの小さなウィンドウにする
- タイトルバーをなくし、細い枠だけにする。曲名のあたりをつかんで動かす。右クリックのメニューで、元に戻す・閉じる
- 高さは中身に合わせて固定し、幅だけ変えられる
- ミニモードでは状態の行が隠れるので、エラーとお知らせは見えない

### 配色

- このアプリ独自の配色（Chiyomaru: System / Light / Dark。既定は System）と、Windows の色に従う配色（Windows: System / Light / Dark）から選ぶ
- System は、明るい・暗いを Windows の設定に合わせる
- 独自の配色は、アイコンの色（濃紺、緑、黄）を基調にする。緑が主の色（スライダー、再生ボタン、選択、「BP」の印）、黄が副の色（今の曲、「× BP」の印）

### 設定画面

- 「ファイル」メニューの「設定」（Ctrl+,）から開く。別のウィンドウで、開いたまま再生の操作ができる
- 「OK」「キャンセル」はなく、変えた時点で反映する
- ページ: 出力 / プレイリスト / 起動と関連付け / 表示 / バージョン情報
- 出力デバイス、排他モード、ReplayGain は、再生中に切り替えることが多いので、「出力」メニューにも置く
- バージョン情報には、バージョン、作者、リリースノート、このアプリと依存ライブラリのライセンス文を出す（実行ファイルに埋め込んである）

### キーボードとメディアキー

- ショートカットは固定（カスタマイズはできない）

| 操作 | キー |
|---|---|
| 再生 / 一時停止 | Space |
| 停止 | Ctrl+Space |
| 次の曲 / 前の曲 | Ctrl+→ / Ctrl+← |
| 5 秒進む / 戻る | → / ← |
| 音量を上げる / 下げる | Ctrl+↑ / Ctrl+↓ |
| ミニモード | Ctrl+M |
| 常に手前に表示 | Ctrl+T |
| 設定 | Ctrl+, |
| 選択中の曲を上へ / 下へ | Alt+↑ / Alt+↓ |

- 一覧にフォーカスがあっても効くよう、これらのキーは一覧より先に受け取る。メニューや選択欄を開いている間は、そちらの操作を優先する
- Alt+↑ / Alt+↓ の後で Alt を離すと、Alt だけを押して離したときと同じくメニューバーが選ばれてしまうので、すぐに閉じて、フォーカスを動かした曲の行へ戻す
- メディアキーは、Windows のシステムメディアコントロール経由で受ける（再生、一時停止、停止、次へ、前へ）。Windows のメディア操作パネルに、曲名・アーティスト・アルバムを出す
- 他のアプリからキーを奪う、グローバルホットキーの登録は使わない

### その他

- ハイ DPI に対応する
- Unicode のタグとファイル名を扱える
- 表示の言語は日本語

## 8. 技術選定

**言語は C#、UI は Avalonia、発行の形は Native AOT。**
軽さだけを見れば C++ も選べるが、保守のしやすさから C# を選んだ。

| 項目 | 方針 | 理由・注意 |
|---|---|---|
| ランタイム | .NET 10 + Native AOT（win-x64） | ランタイムを含む単体の実行ファイルになり、利用者側に .NET のインストールが要らない |
| UI | Avalonia 12 | Native AOT に正式に対応している中で、配布サイズとメモリが小さい（8.1） |
| 描画 | ソフトウェア描画 | GPU 描画は、小さなウィンドウでも起動とメモリのコストが大きい（8.2） |
| AOT への配慮 | リフレクションに頼る書き方を避ける | XAML はコンパイル済みバインディング。設定の JSON はソース生成で読み書きする |
| 音声の出力 | NAudio 3.1.0（WASAPI） | 排他モードの形式の決定と詰め替えは自前（3.2） |
| デコード | NAudio と、形式ごとのリーダー | 3.1 のとおり |
| タグの読み取り | 自前の実装 | 必要な項目だけを読むので軽い。依存ライブラリを 1 つ減らせる |
| 構成 | UI に依存しない Core 層と、UI 層 | 再生、デバイス、プレイリスト、設定を、UI なしで単体テストできる |
| ビルド環境 | .NET 10 SDK + Visual Studio の C++ ビルドツール | Native AOT のリンクに必要。リンク時に `vswhere.exe` が見つからない場合は、Visual Studio Installer のフォルダを PATH に足す |

### 8.1 UI フレームワークの比較

最小のアプリ（ボタン 2 個とラベル 1 個のウィンドウで、MP3 を共有モードで 5 秒再生する）を、フレームワークごとに作って測った。各 5 回の中央値。

| 構成 | 配布サイズ | ウィンドウの表示まで | 音が出るまで | ワーキングセット |
|---|---|---|---|---|
| WinForms（ランタイム別途） | 3.1 MB | 130 ms | 158 ms | 54.7 MB |
| WinForms（ランタイム同梱） | 112.3 MB | 127 ms | 158 ms | 54.4 MB |
| WinForms + Native AOT | 14.5 MB | 64 ms | 84 ms | 29.1 MB |
| **Avalonia 12 + Native AOT（採用）** | 35 MB | 198 ms | 216 ms | 81.9 MB |
| WinUI 3 + Native AOT | 120 MB | 197 ms | 215 ms | 91.9 MB |

- WinForms は Native AOT でいちばん軽かったが、公式には対応していないので選ばなかった
- WinUI 3 は、メモリと配布サイズがいちばん大きかった
- Avalonia のこの値は、既定の GPU 描画で測ったもの。ソフトウェア描画にすると、大きく下がる（8.2）

### 8.2 描画方式

同じアプリで、描画の設定だけを変えて測った。

| 描画の設定 | ウィンドウの表示まで | ワーキングセット | プライベートメモリ |
|---|---|---|---|
| 既定（GPU 描画） | 206 ms | 87.3 MB | 158.1 MB |
| **ソフトウェア描画（採用）** | 54 ms | 43.1 MB | 14.8 MB |

- GPU 描画では、プライベートメモリが再生の開始後も増え続け、約 170MB で頭打ちになった。増えていたのは、描画まわりのネイティブのメモリ
- 画面の更新が少ないアプリなので、CPU での描画で足りる

### 8.3 メモリを OS に返す

.NET のヒープは、回収した後の空きを、すぐには OS に返さない。一時オブジェクトがまとまって出る処理の後に、ワーキングセットが増えたままになる。
次の箇所では、処理が終わった時点で 1 回だけ、ヒープを詰めて返している。

| 箇所 | 対策前 | 対策後 |
|---|---|---|
| 10,000 曲のタグを読んだ後 | 約 121MB | 約 69MB |
| 列の幅をドラッグした後 | ドラッグ前より 30〜45MB 多い | ドラッグ前と同じ |
| 設定画面を閉じた後 | 開閉を繰り返すと約 112MB | 開く前より約 5MB 多い |

- タグの読み取りは、1 曲あたり約 8KB の一時オブジェクトを作る（10,000 曲で約 85MB）。200 曲以上をまとめて読み終えたときに回収する
- 回収で止まる時間は、10,000 曲で合計 30ms 程度

### 8.4 計測の方法

- `tools/Measure-Startup.ps1` で、アプリを発行し、音声ファイルを実際に再生して測る
- **計測値は、PC の状態で大きくぶれる。** 同じビルドでも、時間帯によって 30〜40ms、10MB 程度ずれることがある
- 変更の影響を見るときは、変更の前と後のビルドを交互に起動して、中央値で比べる

## 9. 実装で分かったことと、その対処

仕様には表れないが、作りを決めた理由になっているもの。

### 出力

- NAudio の `WasapiPlayer` は、形式が合わないと黙って変換する。排他モードでは、自前で決めた形式が変換なしで通ることを、実行時に確かめる（3.2）
- 排他モードでは、終端と一時停止を無音でつなぐ（3.2）
- 3 チャンネル以上は、スピーカーの配置つきの形式で渡す（3.2）

### 画面（Avalonia）

- メニュー項目のチェックの状態は、双方向にバインドしても、メニューでの操作が設定に書き戻されなかった。表示だけをバインドし、切り替えはクリックで行う
- 配色を実行中に切り替えるときは、テーマごと作り直して入れ替える。使用中のテーマから配色を外しても、適用済みの色が画面に残った
- 右クリックのメニューでは、文字キーで項目を選ぶ操作が効かない。見出しに「(P)」のような表記は付けない
- メニューを閉じた後、フォーカスがメニューの見出しに残ることがある。その間も、再生の操作のキーは受ける
- スライダーにはフォーカスを持たせない。持たせると、空白キーや矢印キーがスライダーに取られる
- メニューのキーの表示は、キーの名前（OemComma）がそのまま出る。「Ctrl+,」に書き換えている
- ミニモードで細い枠だけにしても、上辺にはシステムが描く帯が残る。中身を枠の領域まで広げて、見えないようにしている
- ミニモードの高さは、Windows がドラッグの途中で送ってくる大きさの問い合わせ（`WM_SIZING`）に、今の高さのままの大きさを返して固定している。いったん変えさせてから戻す方式は、操作中に画面が乱れた

### メモリ

- 画像を縮小するときに、描画ライブラリ（Skia）が作る中間の画像が、共有のキャッシュに残る（3000 ピクセル四方の PNG で約 12MB）。アートワークを読むたびに、キャッシュを捨てる
- 長い文書（依存ライブラリのライセンス文は約 15 万文字）は、1 行ずつの一覧にして、見えている行だけを組む。1 つのテキスト欄に入れると、表示するだけで約 18MB を使った

### アイコン

- 実行ファイルに埋め込むアイコンは、`tools/Make-AppIcon.ps1` で、元の画像から複数のサイズ（16〜64 ピクセルは無圧縮、256 ピクセルは PNG）の ICO として作る
- 256 ピクセルの PNG だけの ICO だと、Windows がウィンドウを作るたびに展開して縮小するので、ウィンドウの表示までが約 4ms 延びた
- ウィンドウのアイコンには、実行ファイルに埋め込んだものがそのまま使われる

### タグ

- ファイルの長さは、開いた時点で 1 回だけ取る。他のソフトの書き込みを許して開くと、長さを尋ねるたびに OS への問い合わせになり、16MB のファイルで数秒かかった
- 途中で切ったファイルと、一部を書き換えたファイルを、形式ごとに約 1,500 通り読ませるテストを置いている
- 既存のタグのライブラリで書いたファイルを、そのライブラリと自前の実装の両方で読み、結果が一致することをテストで確かめている

## 10. 未対応のもの

### 見送っているもの

- DirectShow のフィルターを使った、再生できる形式の拡張。COM の定義を手書きする必要があり、Native AOT で動くかも確かめていない
- タスクトレイへの格納、グローバルホットキー
- よく使うプレイリストのクイック選択
- 再生の速度・音程の変更、曲の中の位置のブックマーク
- タイトルの表示の書式の設定

### 分かっている制限

- シフト JIS の判定には限界がある。第 2 水準の漢字だけの文字列と、半角カナ 2 文字以下だけの文字列は、Latin-1 として読まれる。大文字のアクセント付きの文字が 3 つ以上続く欧文は、半角カナとして読まれる。中国語・韓国語の文字コードは試さない
- 右から左へ書く文字だけの長い曲名は、末尾の側から流れる
- ドラッグでの並べ替えの間、挿入する位置を示す線は出していない
- 「次にこの曲から再生」で指定した曲には、印を出していない
- 依存ライブラリのライセンス文は、アプリの中では選択してコピーできない（`THIRD-PARTY-NOTICES.txt` に全文がある）
- 実際に出回っているファイルでのタグの確認は、限られた数しか行っていない
- 拡大率が違うモニターの組み合わせと、モニターを実際に外した状態での起動は、単体テストでしか確かめていない
